# Russian Humanizer · «Живое слово»

> EN: Turns machine-sounding Russian into living prose, grounded in the Russian editorial tradition (Nora Gal, Chukovsky, Rosenthal). Goal is authenticity, not detector evasion.

Инструмент решает одну задачу: вернуть русскому тексту энергию, ясность и ритм живой речи — убрать «машинность», не выхолащивая текст.

**Корневой принцип.** Языковая модель на каждом шаге выбирает статистически самое вероятное продолжение — то, что подходит наибольшему числу контекстов. Отсюда вся машинность: безопасные обобщения, симметрия, дежурные связки, ровный ритм. Очеловечивание — намеренный выбор менее вероятного, но более характерного и конкретного варианта.

**Позиция проекта.** Цель — аутентичность, не антидетекция. Обход AI-детекторов устаревает с каждым их релизом; живой текст — устойчивая ценность. Высокий «балл машинности» у детектора часто значит лишь, что под этот стиль детектор не обучен (формальный текст, неноситель), а не что текст сгенерирован.

## Главное правило: осторожный гибрид

Инструмент **не гильотина**. Он различает два режима (полностью — в `references/automation-policy.md`):

- **Автоматически правит только однозначный мусор** (низкий риск): следы Markdown в нерендерящемся тексте, чат-ботные хвосты («Надеюсь, это поможет!»), льстивые вводные («Отличный вопрос!»), Title Case в русских заголовках, эмодзи-списки, прямые кавычки → «ёлочки».
- **Всё рискованное — предлагает, а не навязывает**: перестройка синтаксиса, замена слов рядом с терминами, пассив, антитезы. Показывает правку и причину; решает человек.

Риск №1 любого humanizer — **переисправление**: если стричь всё под «живую» гребёнку, родится новый штамп — неестественная равномерная бойкость. Поэтому `references/false-positives.md` — первоклассная часть инструмента, а не сноска.

## Алгоритм

### Шаг 0. Определи жанр
Жанр меняет пороги. Прочитай `references/automation-policy.md`. Для деловой переписки, постов, лендингов, публицистики — чистим смело. Для научного, юридического, технического, нормативного текста — модули канцелярита и пассива работают мягко или только предлагают (см. `references/false-positives.md`).

### Шаг 1. Первый проход — по каталогу
Прогони текст против `references/patterns.md` (разделы 1–6). Чини сначала 🔴, потом 🟡, потом 🟢. Возвращай конкретику, действующее лицо, живой ритм. Канцелярит правь по `references/kantselyarit-dict.md`, кальки — по `references/translationese.md`.

### Шаг 2. Проверка границ
Прежде чем зафиксировать каждую правку, сверься с `references/false-positives.md`. Если признак на самом деле норма для этого жанра (пассив в науке, термин-повтор, «является» в юр. определении, реальная антитеза) — не трогай.

### Шаг 3. Аудит «очевидно ИИ?» + второй проход
Перечитай результат свежим взглядом: что выдало бы ИИ человеку, который ненавидит нейросетевой текст? Почти всегда что-то осталось — проскочившее тире, симметричная пара, ровный ритм. Перепиши эти места. Один проход всегда оставляет следы в собственной правке.

### Шаг 4. Сохранность смысла (обязательно)
Живой текст конкретнее машинного, а не беднее. Проверь, что не уехали: числа, даты, имена, отрицания, обязательства, термины, валюта. Принцип проверки — двусторонняя импликация (следует ли «после» из «до» и наоборот). Если правка изменила факт — откати её.

## Что считается «живым» (ориентиры)

- Конкретика вместо усреднения: не «выдающийся эксперт», а что сделал, когда, с каким результатом.
- Прямое утверждение вместо балансиров: не «не просто X, а Y» — скажи, что и почему.
- Рваный ритм вместо монотонии: чередуй длину предложений.
- Глагол вместо отглагольного существительного, тире вместо «является».
- Нормальная русская типографика: «ёлочки», без Title Case, без эмодзи-списков, без следов Markdown.

## Использование в этом проекте (AINovelEdit)

Здесь скилл применяется к **художественному переводу с японского** (роман),
а не к постам и документации. Уточнения:

* Жанр — проза: пороги как для «публицистики смело чистить», но пассив и
  повторы допустимы как стилистический приём чаще, чем в деловом тексте.
  Сомневаешься — сверяйся с `references/false-positives.md`.
* **Цвет/уровень риска маркера (🔴/🟡/🟢) — сигнал риска, а не разрешение
  на правку.** Автоматически исправлять в этом проекте разрешено только
  однозначный низкорисковый мусор: явные опечатки, очевидные технические
  артефакты, однозначные нарушения обязательного форматирования по
  `russian-prose-rules`. Всё остальное — перестройка синтаксиса, замена
  лексики, пассив → актив, изменение порядка слов, антонимические
  конструкции, абстракция → конкретизация, изменение модальных слов,
  терминологически близкие замены, художественная переформулировка —
  **предложить/проверить, а не навязать** (см. `references/automation-policy.md`).
* После каждой правки humanizer обязателен повторный контроль (RECHECK):
  смысл (self-review), JA и EN, терминология (`dictionary.md`), грамматика
  (`russian-grammar-control`), стиль, форматирование (`russian-prose-rules`).
  Humanizer не должен создавать stylistic churn: Leave-Unchanged Accuracy
  важнее количества правок; ноль правок — допустимый итог.
* Источник машинности другой: не «ИИ-писатель», а **калька с английского
  фанатского перевода** — приоритет у `references/translationese.md` и
  `references/kantselyarit-dict.md`.
* Смысловой каркас — японский оригинал (`translates/ja/`). Правка живости не
  имеет права добавлять/убирать факты; при сомнении сверься с EN, затем с JA.
* Имена, названия, титулы — только по `dictionary.md`; правила прямой речи,
  мыслей и типографики — по скиллу `russian-prose-rules` (он старше: сначала
  правильное оформление, потом очеловечивание).
* Работай блоками по границам абзацев из `translates/` — число и порядок
  абзацев менять нельзя.

## Ограничения в этом проекте (перекрывают каталог при конфликте)

1. **Курсив `*…*` и blockquote `>` — НЕ «следы Markdown»**: это функциональная
   разметка по `russian-prose-rules` (мысли, письма, заклинания про себя).
   Маркеры 5.6, 5.8, 5.9 здесь не применяются; вывод проекта — валидный
   рендерящийся markdown.
2. **Модальные слова (1.8, 1.9)** — «возможно, вероятно, кажется, как
   правило» в прозе часто передают модальность японского оригинала. Править
   только после сверки с JA-абзацем; сомнение → не трогать.
3. **Реплики персонажей — голос персонажа**: маркеры 1.5, 6.3, 6.4 внутри
   прямой речи править только при явном машинном мусоре. Характер речи
   («улучшать» манеру героя) запрещён.
4. **Шаг 3 (переписывание ритма)** — не переписывать то, что совпадает по
   структуре с JA-абзацем. Ритм правится только в явном машинном переборе.
5. Всё рискованное — по `automation-policy.md`: не вноси молча, а фиксируй
   в отчёте аудита (`output/_audit/`) как предложение пользователю.
