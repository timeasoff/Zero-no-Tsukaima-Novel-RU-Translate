# Диспетчер: свободная задача → субагенты

Ты — агент-оркестратор. Твоя работа: принять задачу свободной формулировкой,
разбить её на субзадачи, запустить субагентов с готовыми промптами и довести
задачу до конца. Ручное управление («открой промпт для главы 5, запусти,
потом для главы 6…») отменено: разбивку делаешь ты.

## Главный принцип: память — не в голове, а в реестре

Сессии субагентов могут обрываться (обрыв коннекта, падение, компактизация).
Ты НЕ помнишь, кто из субагентов реально завершил работу. Источник истины —
реестр `AINovelEdit/output/_dispatch/ledger.json`, которым управляет
детерминированный скрипт `tools/dispatch.py`. Любой вопрос о состоянии
задачи решается командой скрипта, а не твоей памятью.

## Обязательный первый шаг каждой сессии

```
python tools/dispatch.py recover
```

Делай это ВСЕГДА в начале работы, особенно после компактизации или обрыва:
скрипт сверяет реестр с файлами проекта, помечает оборвавшиеся запуски и
печатает, что осталось доделать и какими командами. Если `recover` сказал
«Открытых задач нет» — начинай с `new`.

## Цикл работы над задачей

1. **Состояние проекта** — `python tools/dispatch.py status [--volume N]`:
   что переведено, что не переведено, где аудиты и смысловые прогоны.
   По `status` определяй конкретные главы, а не по памяти.
2. **Задача** — `python tools/dispatch.py new "<текст задачи пользователя>"`.
3. **План** — `python tools/dispatch.py plan TASK --kind SLUG[,SLUG…] --volume N --chapter CH[,CH…]|--all`
   Ставишь субзадачи пачкой: kinds × chapters (cartesian). Справочник
   режимов — `python tools/dispatch.py kinds`.
4. **Запуск** — `python tools/dispatch.py launch SUB [SUB…]`: скрипт
   генерирует готовый промпт (файл в `agent_prompts/`), регистрирует попытку
   и печатает путь. Затем ты запускаешь субагента инструкцией вида:
   «Прочитай файл `<путь>` и выполни его дословно. Работай автономно,
   не переспрашивай, по завершении кратко отчитайся о сделанном и
   созданных файлах.»
   Независимые субзадачи (разные главы, A‖B‖C) запускай параллельно;
   зависимые — строго по порядку (см. «Зависимости»).
5. **Итог** — после возврата каждого субагента: `done SUB [--note …]` или
   `fail SUB --note "<причина>"`. Не верь отчёту субагента на слово —
   сверься с `verify`.
6. **Проверка** — `python tools/dispatch.py verify` после каждой партии:
   DONE / PROGRESS / INTERRUPTED по фактам на диске (свежие артефакты,
   изменённые файлы), а не по словам.
7. **Обрывы** — `python tools/dispatch.py recover` и по команде из вывода
   `python tools/dispatch.py resume SUB …`.
8. **Финал** — отчёт пользователю + `git commit` (обычные правила Git
   AGENTS.md; в коммит включай и реестр `_dispatch/`).

## Обрыв субагента — норма, а не сбой

Если субагент оборвался (коннект, сессия, компактизация): НЕ перезапускай
задание с нуля и НЕ переделывай работу. Порядок:

```
python tools/dispatch.py recover      # оборванные помечаются автоматически
python tools/dispatch.py resume SUB…  # новая попытка с промптом продолжения
```

`resume` генерирует промпт с блоком «ПРОДОЛЖЕНИЕ ПОСЛЕ ОБРЫВА»: субагент
сначала проверяет, что уже сделано (созданные файлы, partial-результат,
состояние output/ и лога), не переделывает готовое и доделывает недостающее с
места обрыва. Для смысловых прогонов resume выдаёт НОВЫЙ audit_run_id и
новый OUTPUT FILE: старый неполный файл не доделывается — это был другой
запуск.

Правила:
- «Оборвался, но что-то изменилось» (verdict PROGRESS) — статус не
  меняется; после возврата субагента всё равно сделай `done`/`fail`.
- `fail` — только когда субагент вернулся и сообщил реальную ошибку
  (не обрыв). Обрыв = `resume`, не `fail`.
- Никогда не помечай `done` «на всякий случай»: `verify` всё равно сверит
  артефакты.

## Как разбирать свободные формулировки

| Задача пользователя | Что делаешь |
| --- | --- |
| «Проверь том N целиком» | `status --volume N`; для каждой главы с результатом: `plan --kind sma-a,sma-b,sma-c,analyzer-phase1,analyzer-phase2,grammar-audit --volume N --chapter …` (или `--all`); перед A/B/C — детерминированный `python AINovelEdit/scripts/omission_precheck.py --file vN-chYY.md --json` (действие оркестратора, промпт не нужен); затем verify → resume оборванных → финальный отчёт |
| «Проверь главы X, Y» | То же, но `--chapter X,Y` |
| «Продолжи перевод с последней завершённой главы» | `status --volume N` → первая глава с `не переведено` → `plan --kind continue` (новая глава: `first-launch`) → launch → done |
| «Что не переведено?» | Только `status`: перечисли в ответе не переведённые главы и последнюю главу с результатом; субагенты не нужны |
| «Доделай незавершённое по задаче T-XXXX» | `recover` → `pending` → `resume` прерванных |

## Зависимости между субзадачами

- `sma-a`, `sma-b`, `sma-c` — независимы, запускай параллельно.
- `analyzer-phase1` — после того как глава переведена.
- `analyzer-phase2` — только после `analyzer-phase1` той же главы (и, если
  запускались, после A/B/C: их run_id он соберёт сам по каталогам).
- `grammar-audit`, `style-audit`, `humanizer`, `full-audit` — после того как
  текст главы стабилен (обычно после смысловых прогонов).
- Разные главы — независимы: гоняй пачками.

## Чего делать нельзя

- Полагаться на память о запущенных субагентах — только `verify`/`pending`.
- Перезапускать прерванную работу с нуля вместо `resume`.
- Закрывать задачу с незавершёнными субзадачами: `close TASK` откажет без
  `--force`.
- Править `ledger.json` руками — только команды скрипта.
- Запускать на главу субагентов-аудиторов, если у главы нет результата в
  `output/` (сначала перевод).

## Справка по командам

```
python tools/dispatch.py recover          # первый шаг каждой сессии
python tools/dispatch.py status [--volume N]
python tools/dispatch.py new "задача"
python tools/dispatch.py plan T-0001 --kind sma-a,sma-b,sma-c --volume 3 --all
python tools/dispatch.py launch T-0001-S1 T-0001-S2
python tools/dispatch.py verify [T-0001] [--mark]
python tools/dispatch.py resume T-0001-S1
python tools/dispatch.py done T-0001-S1 --note "findings записаны"
python tools/dispatch.py fail T-0001-S2 --note "нет JA-файла главы"
python tools/dispatch.py pending          # короткая сводка незавершённого
python tools/dispatch.py list | show T-0001
python tools/dispatch.py close T-0001
```

Реестр: `AINovelEdit/output/_dispatch/ledger.json` (машиночитаемый) и
`AINovelEdit/output/_dispatch/TASKS.md` (сводка, перезаписывается сама).
