# Сохранение результата

Единственный способ записи в `output/` — скрипт `scripts/save_block.py`
(запускать из корня проекта). Прямая запись файлов агентом запрещена.

**НЕ РЕДАКТИРУЙ `translates/{ja,en,ru}/*.md` — исходники ТОЛЬКО ДЛЯ ЧТЕНИЯ**
(физически read-only). Результат работы — только `output/` (и
`output/_log/`); merged-файлы — только через `scripts/update_merged.py`.
Проверка целостности translates — посимвольная сверка с git, никогда не
«ремонт» правкой файлов.

## Размер блока

10–20 абзацев (строк) за одну итерацию. Блок = подряд идущие строки исходных
файлов из `translates/`.

## Команды

Первый блок главы (файл создаётся заново):

```
python scripts/save_block.py --file v14-ch01.md --new --block 1 --text "..."
```

Все последующие блоки (только дописывание):

```
python scripts/save_block.py --file v14-ch01.md --block 2 --text "..."
```

Длинный текст можно передать через stdin:

```
$text = @'
...текст блока...
'@
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
$text | python scripts/save_block.py --file v14-ch01.md --block 3
```

ВНИМАНИЕ (Windows/PowerShell): без явной установки `$OutputEncoding` в UTF-8
конвейер перекодирует кириллицу в `?`. Надёжнее передавать текст аргументом:
`python scripts/save_block.py ... --text $text`. После каждой записи
обязательно проверяй, что в файле нет знаков «?» вместо букв.

## Контроль записи

Скрипт печатает число символов и размер файла. Правило проверки:
размер файла в байтах должен быть заметно больше числа символов
(кириллица в UTF-8 занимает 2 байта). Если размер ≈ числу символов —
текст испорчен кодировкой: удали блок и перезапиши через `--text`.

Дополнительно `save_block.py` сразу после записи сверяет позиции абзацев
результата с EN-якорем (профилактика съезда строк) и печатает
предупреждение `(!) позиции: N абзацев ближе к соседней EN-строке…`
вместе с номером первого съехавшего абзаца. Это значит: разбиение блока
не следует EN — поправь блок и разбери план пересадки:

```
python scripts/check_alignment.py --file vXX-chYY.md --propose --report
```

Молча оставлять такое предупреждение нельзя: съезд имеет свойство
накапливаться на всю главу.

## Формат сохраняемого текста

* Первая строка файла (только в блоке 1): заголовок `# <название главы на русском>`.
* Дальше — абзацы, разделённые пустой строкой (как в `translates/`).
* **Число абзацев результата = числу EN-абзацев блока.** Не склеивай и не
  дроби абзацы, даже если JA-абзац крупнее и покрывает два EN: разбиение
  всегда следует EN — к нему привязаны merged (ED_RU) и иллюстрации.
  Если JA-абзац покрывает два EN-абзаца — раздели перевод соответственно.
  Это структурное требование пайплайна, а не утверждение, что EN —
  смысловой эталон: соответствие EN нужно для merged/alignment, смысл
  проверяется по JA.
* **Осторожно с RU-колонкой:** RU выровнен по EN якорным посиднеечным
  алгоритмом (длина + числа + имена; логика едина в tools/normalize.py и
  scripts/update_merged.py), поэтому позиционных сдвигов больше нет.
  Однако сам RU — машинный перевод и местами семантически мутный: он
  вспомогательное сырьё, семантический якорь строки — JA/EN. Короткие
  EN-абзацы (одна реплика) обязаны остаться отдельными абзацами результата.
* **Alignment-сигнал ≠ доказательство ошибки.** Сырой `translates/ru`
  может содержать смещения; JA может иметь известные сдвиги относительно
  EN/RU (`ja-shift`), которые сами по себе не являются ошибкой. Сигнал
  `check_alignment.py` — структурное подозрение: известное смещение
  признаётся артефактом только после проверки соответствующего JA → RU
  участка по смыслу. Запрещено объединять/дробить абзацы «ради красоты»
  или ритма и считать каждый JA-shift ошибкой.
* Строки-комментарии `<!-- ??? -->` разрешены для сомнительных мест, НО
  пишутся В КОНЦЕ строки соответствующего абзаца, не отдельным блоком —
  иначе скрипт update_merged.py собьёт соответствие ED_RU ↔ EN-абзацам.
* Неподтверждённые (provisional) решения — новый термин, рабочая форма
  обращения и т. п. — НЕ блокируют сохранение блока: фиксируй их в
  журнале с пометкой `PROVISIONAL` и перечнем мест использования
  (AGENTS.md, «Неопределённость»; UNCERTAINTY ≠ STOP, PROVISIONAL ≠
  CANONICAL).
* Маркеры `<!-- нет пары в JA -->` из исходников в результат НЕ переносить.

## Восстановление после сбоя

Прогресс = маркеры `<!-- block: N -->` в файлах `output/`. Перед началом
работы найди последний блок каждой главы и продолжай со следующего.
Число блоков в файле = число успешно завершённых итераций.

## Обязательное обновление merged

После КАЖДОГО сохранения блока (и после правок через fix_block.py) обновляй
трёхъязычный файл главы:

```
python scripts/update_merged.py --file v14-ch01.md
```

Скрипт переносит отредактированный текст в поле **ED_RU** файла
`translates/_report/merged/v14-*.md`, сопоставляя абзацы с EN-строками
(ED_RU — источник для итоговой склейки перевода с иллюстрациями).
Merged-файлы руками не редактировать — только через этот скрипт.
Если скрипт печатает предупреждение «ED_RU N != EN M» — число абзацев
результата разошлось с исходником: исправь блок.
