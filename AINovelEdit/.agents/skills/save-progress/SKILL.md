# Сохранение результата

Единственный способ записи в `output/` — скрипты `scripts/save_block.py` (дозапись)
(запускать из корня проекта). Прямая запись файлов агентом запрещена.

**НЕ РЕДАКТИРУЙ `translates/{ja,en,ru}/*.md` — исходники ТОЛЬКО ДЛЯ ЧТЕНИЯ**
(физически read-only). Результат работы — только `output/` (и
`output/_log/`); merged-файлы — только через `scripts/update_merged.py`.
Проверка целостности translates — посимвольная сверка с git, никогда не
«ремонт» правкой файлов.

## Размер блока

Единица итерации — **смысловой блок** из `translates/` (маркер
`<!-- block: N -->`). Нормализация режет текст так, что один блок — одна
микросцена (реплика + атрибуция, диалоговая пара, короткая наррация; обычно
1–8 абзацев). Обрабатывай и сохраняй **один смысловой блок за итерацию**;
крупный блок сохраняй одной записью (`fix_block.py` заменяет блок целиком).

## Команды

Первый блок главы (файл создаётся заново):

```
python scripts/save_block.py --file v14-ch01.md --new --block 1 --text "..."
```

Все последующие блоки (только дописывание):

```
python scripts/save_block.py --file v14-ch01.md --block 2 --text "..."
```

Длинный текст можно передать через stdin:

```
$text = @'
...текст блока...
'@
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
$text | python scripts/save_block.py --file v14-ch01.md --block 3
```

ВНИМАНИЕ (Windows/PowerShell): без явной установки `$OutputEncoding` в UTF-8
конвейер перекодирует кириллицу в `?`. Надёжнее передавать текст аргументом:
`python scripts/save_block.py ... --text $text`. После каждой записи
обязательно проверяй, что в файле нет знаков «?» вместо букв.

## Контроль записи

Скрипт печатает число символов и размер файла. Правило проверки:
размер файла в байтах должен быть заметно больше числа символов
(кириллица в UTF-8 занимает 2 байта). Если размер ≈ числу символов —
текст испорчен кодировкой: удали блок и перезапиши через `--text`.

Дополнительно `save_block.py` сразу после записи сверяет номера блоков: каждый
блок в `output/` обязан существовать в `translates/en` (печатает
`(!) блоки … отсутствуют в EN-исходнике` или `(!) в результате N блоков…`).
Это значит: номер смыслового блока сдвинут или добавлен лишний — поправь блок.
Проверь соответствие блоков:

```
python scripts/check_alignment.py --file vXX-chYY.md --report
```

Молча оставлять такое предупреждение нельзя.

## Формат сохраняемого текста

* Первая строка файла (только в блоке 1): заголовок `# <название главы на русском>`.
* Дальше — блоки, размеченные `<!-- block: N -->`; внутри блока абзацы
  разделяются пустой строкой (как в `translates/`).
* **Число блоков результата = числу смысловых блоков исходника.** Абзацную
  структуру русского текста внутри блока выбираешь сам по правилам
  `russian-prose-rules` — можно свободно делить и объединять предложения,
  если смысл JA сохранён; границу блока (`<!-- block: N -->`) не переносить,
  номер блока не менять. Смысл сверяется по блоку JA целиком
  (EN — вспомогательный).
* Внутри блока пустая строка = новый абзац (это разрешено); между блоками
  границу задаёт **только** маркер `<!-- block: N -->`.
* **RU-колонка — вспомогательное сырьё.** RU — машинный перевод и местами
  семантически мутный; смысловой якорь блока — JA (в помощь EN). RU привязан
  к блокам при нормализации (`tools/normalize.py`), но границы EN/RU могут сдвигаться на соседние сцены (AGENTS.md, «Известные ограничения»).
* **Сигнал check_alignment.py ≠ доказательство ошибки.** Блоки JA/EN/RU
  выровнены при нормализации, но границы сдвигаются; сигнал (речь, знаки,
  отрицание, числа, имена) — структурное подозрение внутри блока, разбор по
  скиллу translation-audit. Запрещено дробить/сливать блоки «ради красоты».
* Строки-комментарии `<!-- ??? -->` разрешены для сомнительных мест и
  пишутся В КОНЦЕ соответствующего абзаца, не отдельным блоком — иначе
  разбор блока в merged отнесёт комментарий не туда.
* Неподтверждённые (provisional) решения — новый термин, рабочая форма
  обращения и т. п. — НЕ блокируют сохранение блока: фиксируй их в
  журнале с пометкой `PROVISIONAL` и перечнем мест использования
  (AGENTS.md, «Неопределённость»; UNCERTAINTY ≠ STOP, PROVISIONAL ≠
  CANONICAL).
* Расхождение термина/имени/обращения с **завершённым томом**
  (`completed.md`) фиксируй в журнале и в отчёте аудита, но используй форму
  из завершённого тома (исключение — ручная правка словаря пользователем).

## Восстановление после сбоя

Прогресс = маркеры `<!-- block: N -->` в файлах `output/`. Перед началом
работы найди последний блок каждой главы и продолжай со следующего.
Число блоков в файле = число успешно завершённых итераций.

Если маркеров нет, глава ещё не начата: начинай блок 1 (`--new --block 1`)
в этом же запуске после первичной проверки, не дожидаясь отдельного
разрешения пользователя (AGENTS.md, «Правила работы»: первичная проверка —
подготовительный этап; скилл `novel-editor`).

## Обязательное обновление merged

После КАЖДОГО сохранения блока (и после правок через fix_block.py) обновляй
трёхъязычный файл главы:

```
python scripts/update_merged.py --file v14-ch01.md
```

Скрипт переносит отредактированный текст в поле **ED_RU** файла
`translates/_report/merged/*.md` по смысловым блокам (маркеры `<!-- block: N -->`),
(ED_RU — источник для итоговой склейки перевода с иллюстрациями; в новых томах абзацы ED_RU НЕ привязаны к строкам EN 1:1).
Merged-файлы руками не редактировать — только через этот скрипт.
Если скрипт печатает предупреждение «ED_RU N != EN M» — число абзацев
результата разошлось с исходником: исправь блок.
