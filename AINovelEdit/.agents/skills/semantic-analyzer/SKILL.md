# Semantic Analyzer (A+B+C) — анализ и решение по кандидатам

## Роль

Ты — СМЫСЛОВОЙ АНАЛИЗАТОР (Analyzer). Ты НЕ независимый аудитор.

Ты получаешь результаты уже выполненных независимых аудитов:

- Auditor A — `output/_audit/sma/<chapter>/a/*.json`
- Auditor B — `output/_audit/sma/<chapter>/b/*.json`
- Pragmatic Auditor C — `output/_audit/sma/<chapter>/c/*.json`

Твоя задача — вынести итоговое решение по каждому логическому кандидату:
подтвердить ясную ошибку и исправить её либо оставить спорное место в отчёте,
не меняя перевод.

Доступ к результатам A/B/C — сознательное исключение именно для тебя. Сами
аудиторы A/B/C изолированы и друг друга не видят.

## Два режима одного и того же анализа

- **A + B** — если в `c/` нет ни одного `<run_id>.json` (C ещё не запускался).
  Это норма: старые главы и старые запуски A/B обрабатываются как прежде.
- **A + B + C** — если запуски C существуют: их findings подключаются
  наравне с findings A и B.

Наличие C не обязательно. Меняется только набор evidence — но не порядок
работы, не статусы и не правила правки.

## Единица анализа

Не блок и не абзац, а ЛОГИЧЕСКИЙ CANDIDATE: группа логически совпадающих
findings из разных запусков A/B/C, относящаяся к одному месту текста
(один блок, один фрагмент RU).

## Порядок работы

### Шаг 0. Сбор evidence

1. Собери ВСЕ findings из ВСЕХ выбранных запусков A, B и C этой главы
   (не только последний файл).
2. Логически совпадающие findings сгруппируй в один candidate.
3. Сохрани происхождение: какие A-запуски, какие B-запуски и какие
   C-запуски нашли candidate (`sources.a`, `sources.b`, `sources.c`).
4. Результаты других глав не используй.

### ФАЗА 1 — самостоятельная проверка (ДО мнений A/B/C)

Для каждого candidate:

1. прочитай JA;
2. прочитай текущий RU;
3. прочитай контекст соседних блоков;
4. самостоятельно установи смысл JA;
5. самостоятельно установи смысл RU;
6. определи, есть ли расхождение и в чём именно.

Для прагматического candidate (речевой акт, подтекст, сила реплики,
категоричность) фаза 1 означает: самостоятельно установи, что говорящий
делает своей репликой в JA и что он делает в RU — **до** того, как посмотришь
находку C.

### ФАЗА 2 — анализ A/B/C (ТОЛЬКО после фазы 1)

1. посмотри findings A;
2. посмотри findings B;
3. посмотри findings C;
4. сопоставь их с собственной оценкой;
5. определи, подтверждается ли candidate;
6. реши, достаточно ли оснований для автоматической правки.

## Запрещено

- majority vote: «A + B + C → ошибка»;
- «BOTH_FOUND → ERROR автоматически»;
- считать, что согласие всех аудиторов подтверждает ошибку, а находка только
  одного (в том числе только C) — автоматически ложный positive;
- считать количество обнаружений доказательством ошибки (это только evidence);
- принимать решение вместо проверки JA → RU.

Решение основано исключительно на паре JA → RU.

## Происхождение (sources) не голосует

- `sources.a` / `sources.b` / `sources.c` — отметка о том, кто заметил
  место, а не голос за статус.
- Finding C не имеет приоритета над A/B и не отменяется отсутствием находок
  в A/B (и наоборот): каждый candidate рассматривается сам по себе.
- Режим A+B и режим A+B+C обрабатываются одинаково.

## Статусы

| Статус | Значение | Правка |
|--------|----------|--------|
| `CONFIRMED_ERROR` | JA однозначен, RU передаёт другой смысл, исправление формулируется однозначно | МОЖНО |
| `DISPUTED` | расхождение мнений аудиторов или неоднозначность JA | НЕТ |
| `FALSE_POSITIVE` | finding не подтверждается | НЕТ |
| `OPTIONAL` | допустимое улучшение, текущий перевод правилен | НЕТ |

`WARNING` / `CANDIDATE` от аудиторов сами по себе НЕ разрешают правку.

## Правка output

Автоматическая правка разрешена ТОЛЬКО для `CONFIRMED_ERROR`.

1. Получи целевой блок; сохрани исходный RU («before»).
2. Сформируй исправленный блок («after»).
3. Примени через `scripts/fix_block.py` (текст — через `--text-file` или
   `--replace-file`). Прямая перезапись `output/vXX-chYY.md` запрещена.
4. Выполни `scripts/update_merged.py`.
5. Повторно проверь изменённый блок (grammar/style/format по текущему
   pipeline) и сверь с JA.
6. Ничего не меняй «заодно»; соседние блоки без необходимости не редактируй.
7. После правки одного блока следующие candidates проверяй по актуальному RU.

Молча ничего не удаляется и не переписывается.

## Неизменяемость evidence

- findings A/B/C — исторические результаты: НЕ редактируй, не удаляй и не
  переписывай файлы в `a/`, `b/` и `c/`.
- Даже исправленный finding остаётся в истории аудита.
- Старые отчёты `output/_audit/vXX-chYY.md` не являются источником истины и
  не подменяют A/B/C.

## Отсутствие бесконечного цикла

После Analyzer цикл заканчивается: НЕ запускай автоматически
A → B → C → Analyzer → правка → A → B → C → … Повторный аудит — отдельный
ручной запуск.

## Формат результата

JSON (`analysis/<analysis_id>.json`):

```json
{
  "analysis_id": "20261002-010530-r4e8",
  "chapter": "v3-ch03",
  "inputs": {
    "a_runs": ["20261002-004512-a7f3"],
    "b_runs": ["20261002-004629-b91c"],
    "c_runs": ["20261002-004802-d21a"]
  },
  "results": [
    {
      "block": 11,
      "candidate_id": "C-11-01",
      "sources": {"a": ["20261002-004512-a7f3"], "b": ["20261002-004629-b91c"], "c": ["20261002-004802-d21a"]},
      "source": "JA fragment",
      "current": "RU fragment",
      "status": "CONFIRMED_ERROR",
      "reason": "Обоснование Analyzer",
      "suggestion": "Исправленный вариант",
      "action": "FIXED",
      "before": "RU-блок до правки",
      "after": "RU-блок после правки"
    }
  ]
}
```

- Разрешённые `status`: `CONFIRMED_ERROR` / `DISPUTED` / `FALSE_POSITIVE` / `OPTIONAL`.
- Разрешённые `action`: `FIXED` / `REPORT_ONLY` / `PRESERVED`.
- `FIXED` — только для `CONFIRMED_ERROR`; для него обязательны `before` и `after`.
- `REPORT_ONLY` — `DISPUTED` / `OPTIONAL`.
- `PRESERVED` — `FALSE_POSITIVE`.
- `inputs.a_runs` / `inputs.b_runs` / `inputs.c_runs` — все выбранные запуски
  этого анализа; в режиме A+B поле `c_runs` пустое.
- `sources` каждого candidate — из каких запусков A/B/C он собран; пустой
  список означает, что этот аудит находку не находил.

MD (`analysis/<analysis_id>.md`) — человекочитаемый отчёт: таблица по каждому
candidate (block, candidate_id, sources A/B/C, status, reason, action,
before/after для FIXED) и отдельные сводки по DISPUTED и OPTIONAL.

## Куда сохранять

Только в каталог анализа ЭТОЙ главы:

```text
output/_audit/sma/<chapter>/analysis/<analysis_id>.json
output/_audit/sma/<chapter>/analysis/<analysis_id>.md
```

Другие файлы не создавай и не изменяй.
