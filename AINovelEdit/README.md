# AINovelEdit — улучшение машинного RU-перевода новеллы

> **Инструкция для человека — [РУКОВОДСТВО.md](РУКОВОДСТВО.md) (от А до Я).**
> Этот README — техническое описание проекта.

Изолированная среда для агента Cline: глава за главой превращает машинный
русский перевод японской новеллы в художественный текст, сверяясь с
японским оригиналом и английским переводом.

## Структура

```text
AINovelEdit/
├── .agents/skills/              # системные инструкции для Cline
│   ├── novel-editor/            # роль и рабочий процесс
│   ├── terminology-dictionary/  # правила словаря
│   ├── self-review/             # проверка на галлюцинации
│   ├── translation-audit/       # независимая сверка смысла с JA/EN
│   ├── russian-prose-rules/     # правила русской прозы: речь, мысли, курсив
│   ├── russian-humanizer/       # внешн. скилл (MIT): канцелярит, translationese,
│   │                             #   AI-штампы → живой текст; references/ внутри
│   ├── russian-grammar-control/ # морфология, согласование, управление,
│   │                             #   залог и актанты (после редактуры)
│   ├── russian-style-audit/     # финальный стилевой аудит: тавтология, повторы,
│   │                             #   избыточность, коллокации, кальки
│   ├── forms-of-address/        # обращения к персонажам (addresses.md)
│   └── save-progress/           # поблочное сохранение
├── scripts/
│   ├── save_block.py            # дозапись блоков в output/ (основная запись)
│   ├── fix_block.py             # точечная замена блока (исправления по аудиту)
│   ├── grammar_scan.py          # предфильтр грамматики: кандидаты по merged
│   │                             #   (EN-пассив ↔ RU -ся, «X's Y was …», «был + причастие»)
│   ├── style_scan.py            # предфильтр стиля: кандидаты на тавтологию,
│   │                             #   повторы, избыточность, коллокации и т. п.
│   └── check_alignment.py       # построчная сверка merged: съезд ED_RU ↔ EN-якоря
│                                 #   (+ --propose: план пересадки абзацев)
├── translates/                  # нормализованные данные (генерируются скриптом)
│   ├── ja/  en/  ru/            # абзацы, разделённые пустой строкой; абзац №N
│   │                             # соответствует абзацу №N в остальных языках
│   └── _report/                 # отчёт о выравнивании + merged/ (зеркало output/)
├── output/                      # РЕЗУЛЬТАТ работы агента
│   ├── _log/                    # журнал решений (удаления, сомнения, термины)
│   └── _audit/                  # отчёты аудита глав; _prefilter/ — выгрузки предфильтров
└── dictionary.md                # абсолютная истина по терминам (вики-соглашение)
```

### Структура аудита

Аудит разделён на независимые слои. Каждый слой ищет свой класс
ошибок и не должен подменять следующий или предыдущий.

```text
translation-audit
↓
Смысл / соответствие JA и EN
↓
novel-editor
↓
Художественная редактура
↓
russian-humanizer
↓
Машинность / translationese / AI-штампы
↓
russian-prose-rules
↓
Оформление русской прозы
↓
russian-grammar-control
↓
Грамматика / управление / падежи / актанты / залог
↓
style_scan.py
↓
Механический поиск стилевых кандидатов
↓
russian-style-audit
↓
Тавтология / повторы / коллокации / избыточность / кальки
↓
FINAL AUDIT
↓
Проверка результата по всем слоям
```

```text
                СМЫСЛ
                  │
         translation-audit
                  │
                  ▼
             РЕДАКТУРА
                  │
            novel-editor
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
   humanizer          prose-rules
        │                   │
        └─────────┬─────────┘
                  ▼
              ГРАММАТИКА
                  │
       russian-grammar-control
                  │
                  ▼
          grammar_scan.py
                  │
                  ▼
               СТИЛЬ
                  │
            style_scan.py
                  │
                  ▼
        russian-style-audit
                  │
                  ▼

```

> **Важно:** `grammar_scan.py` и `style_scan.py` — механические
> предфильтры кандидатов, а не источники окончательного решения.
> Финальное решение принимает соответствующий аудит с учётом контекста.

Рядом с README лежат `addresses.md` (справочник обращений: мадемуазель/
мадам/месье по прототипам королевств + конкретные персонажи) и
`РУКОВОДСТВО.md` (инструкция для человека).

## Внешние скиллы: что подключено и почему

| Скилл                                | Статус                          | Оценка применимости к этой задаче                                                                                                                                                                                                                                                                                                                                                                |
| ------------------------------------ | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `russian-humanizer` (MIT)            | подключён, `references/` внутри | ядро «очеловечивания»: канцелярит, translationese, AI-штампы                                                                                                                                                                                                                                                                                                                                     |
| `talkstream/ru-text` (MIT)           | не подключён                    | вычитка и типографика русского текста, который автор пишет сам: 17 признаков нейрослопа, рубрика 0–10. Сверки с JA/EN не делает, исходник не знает, поэтому морфологию и актанты перевода не ловит. Пересекается с уже подключёнными `russian-humanizer` и `russian-prose-rules`; как «финальный грамматический редактор» не годится — только как внешняя вычитка готовой главы глазами человека |
| `Anic888/russian-text-quality` (MIT) | не подключён                    | предмет — баги русского в коде и i18n (CLDR-плюрализация, конкатенация строк, транслит-идентификаторы). Прозу прямо объявляет вне области: «Prose quality is delegated to other tools». Для художественного перевода неприменим                                                                                                                                                                  |

Вывод: класс ошибок «смещены актанты / сломан залог / рассогласование»
внешними скиллами не закрывается — он снимается собственным слоем
`russian-grammar-control` + механическим предфильтром
`scripts/grammar_scan.py`, который работает по сверке с EN/JA, а не по
«похоже на живой русский».

## Подготовка данных (вне проекта)

Сырые файлы кладутся в `../origs/` как `<том>-ja.epub`, `<том>-en.pdf` и
RU-источник: `<том>-ru.docx` **или** `<том>-ru.md` (уже правленный перевод в
markdown — приоритет у docx, если лежат оба). Для RU-md: абзацы разделяются
пустой строкой, главы — заголовками `# Глава N: ...`; переносы строк внутри
абзаца склеиваются автоматически. Совпадение числа абзацев с оригиналом не
требуется — выравнивание DP разрезает склеенные и приклеивает лишние абзацы
к соседним. Если заголовков глав в md нет вовсе, абзацы распределяются по
главам EN пропорционально объёму (границы получаются приблизительными).

Затем из корня репозитория:

```bash
python tools/normalize.py --volume 14
```

Скрипт извлекает текст из всех трёх форматов, чистит его и выравнивает
абзацы трёх языков друг против друга (отчёт — в `translates/_report/`).

## Запуск агента

Открыть `AINovelEdit/` в Cline и дать задачу, например:

> Продолжай редактирование тома 14 по скиллам: возьми первую неоконченную
> главу из translates/, работай блоками по 10–20 строк и сохраняй результат
> через scripts/save_block.py.

Агент сам найдёт незавершённые главы по маркерам `<!-- block: N -->` в `output/`.
Все отклонения от источников (удаления, расхождения JA↔EN, сомнения) агент
фиксирует в `output/_log/vNN-log.md` — молча ничего не удаляется; места,
требующие вашего решения, помечаются `<!-- ??? -->`.

## Известные ограничения нормализации

- Выравнивание JA↔EN/RU приблизительное (по длинам абзацев): JA может быть
  сдвинут на ±1–2 строки, редкие абзацы склеены. Агент выравнивает по смыслу.
- Пустые JA-строки в середине файла — место, где JA-абзац не нашёл пары.
