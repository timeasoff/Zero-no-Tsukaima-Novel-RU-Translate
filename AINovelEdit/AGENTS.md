# AGENTS.md — общие указания для агента (AINovelEdit)

## Назначение

Проект доводит машинный русский перевод японской новеллы до художественного
состояния, сверяясь с японским оригиналом (JA) и английским переводом (EN).

**Главная задача — не переводить текст заново**, а редактировать существующий
русский перевод, сохраняя смысл оригинала.

## Приоритет источников

- **JA — главный источник смысла.**
- **EN — вспомогательный источник** для сопоставления и дополнительного
  контекста.
- Не считать английскую формулировку более правильной, если она расходится
  с японским оригиналом; расхождения JA ↔ EN фиксировать в логе.

## Структура каталогов

Корень рабочей директории агента — `AINovelEdit/`. Конкретные абсолютные пути
для текущего тома/главы указываются в промпте, который генерируется
инструментом `tools/generate_agent_prompt.py` (не меняй пути вручную).

```text
AINovelEdit/
├── .agents/skills/              # системные инструкции (скиллы), см. ниже
├── scripts/
│   ├── save_block.py            # дозапись блоков в output/ (основная запись)
│   ├── fix_block.py             # точечная замена блока (исправления по аудиту)
│   ├── grammar_scan.py          # предфильтр грамматики: EN-пассив ↔ RU -ся,
│   │                            #   «X's Y was …», «был + причастие»
│   ├── style_scan.py            # предфильтр стиля: тавтология, повторы,
│   │                            #   избыточность, коллокации
│   ├── check_alignment.py       # построчная сверка merged: съезд ED_RU ↔ EN
│   │                            #   (+ --propose: план пересадки абзацев)
│   └── update_merged.py         # обновление зеркала merged/
├── translates/
│   ├── ja/  en/  ru/            # абзацы, разделённые пустой строкой;
│   │                            #   абзац №N соответствует №N в других языках
│   └── _report/                 # отчёт о выравнивании + merged/ (зеркало output/)
├── output/                      # РЕЗУЛЬТАТ работы агента
│   ├── vNN-chYY.md              # финальный отредактированный текст
│   ├── _log/vNN-log.md          # журнал решений (удаления, сомнения, термины)
│   └── _audit/vNN-chYY.md       # отчёты аудита; _audit/_prefilter/ — предфильтры
├── dictionary.md                # абсолютная истина по терминам
└── addresses.md                 # справочник обращений к персонажам
```

## Правила работы

- Работай по главам, блоками по 10–20 строк; результат сохраняй через
  `scripts/save_block.py`, точечные исправления — через `scripts/fix_block.py`.
- Незавершённые главы находятся по маркерам `<!-- block: N -->` в `output/`.
- Все отклонения от источников (удаления, расхождения JA ↔ EN, сомнения)
  фиксируются в `output/_log/vNN-log.md`. **Молча ничего не удаляется.**
- Места, требующие решения человека, помечаются `<!-- ??? -->`.
- Термины — только по `dictionary.md`; обращения к персонажам — по
  `addresses.md`.
- Перед изменением текста учитывай этот файл, словарь и правила скиллов.

## Порядок обработки (pipeline)

Слои аудита независимы: каждый ищет свой класс ошибок и не подменяет соседний.

```text
translation-audit       → смысл / соответствие JA и EN (EN — эталон, JA — арбитр)
novel-editor            → художественная редактура
self-review             → самопроверка на галлюцинации (перед сохранением)
save-progress           → сохранение через save_block.py
                          + update_merged.py + check_alignment.py
russian-humanizer       → машинность / translationese / AI-штампы
russian-prose-rules     → оформление русской прозы (речь, мысли, курсив)
grammar_scan.py         → шаг 0: механический предфильтр грамматических кандидатов
russian-grammar-control → грамматика / падежи / актанты / залог (разбор кандидатов)
style_scan.py           → механический предфильтр стилевых кандидатов
russian-style-audit     → тавтология / повторы / коллокации / кальки
FINAL AUDIT             → проверка результата по всем слоям (итоги GRAMMAR и STYLE)
```

**Важно:** `grammar_scan.py` и `style_scan.py` — механические предфильтры
кандидатов, а не источник окончательного решения. Финальное решение принимает
соответствующий аудит-скилл с учётом контекста; не исправляй текст
автоматически только потому, что сканер что-то отметил.

## Скиллы (`.agents/skills/`)

| Скилл | Назначение |
| --- | --- |
| `novel-editor` | роль и рабочий процесс художественной редактуры |
| `terminology-dictionary` | правила работы со словарём терминов |
| `self-review` | самопроверка на галлюцинации |
| `translation-audit` | независимая сверка смысла с JA/EN |
| `russian-prose-rules` | правила русской прозы: речь, мысли, курсив |
| `russian-humanizer` | внешн. скилл (MIT): канцелярит, translationese, AI-штампы → живой текст; `references/` внутри |
| `russian-grammar-control` | морфология, согласование, управление, залог и актанты (после редактуры) |
| `russian-style-audit` | финальный стилевой аудит: тавтология, повторы, избыточность, коллокации, кальки |
| `forms-of-address` | обращения к персонажам (`addresses.md`) |
| `save-progress` | поблочное сохранение результата |

Внешний скилл `russian-humanizer` подключён как ядро «очеловечивания».
Класс ошибок «смещены актанты / сломан залог / рассогласование» внешними
скиллами не закрывается — он снимается слоем `russian-grammar-control`
и предфильтром `scripts/grammar_scan.py` (работает по сверке с EN/JA,
а не по «похоже на живой русский»).

## Известные ограничения нормализации

- Выравнивание JA ↔ EN/RU приблизительное (по длинам абзацев): JA может быть
  сдвинут на ±1–2 строки, редкие абзацы склеены. Выравнивай по смыслу.
- Пустые JA-строки в середине файла — место, где JA-абзац не нашёл пары.
