# Руководство пользователя — от А до Я

Это инструкция для вас (человека). Агент работает по скиллам в
`.agents/skills/`, а вы по этому файлу.

## Шаг 0. Как это устроено (30 секунд)

1. Вы кладёте сырой том в 3 форматах в папку `origs/`.
2. Скрипт нормализации превращает их в выровненные абзац-к-абзацу файлы
   в `translates/`.
3. Агент Cline в папке `AINovelEdit/` редактирует русский перевод главами,
   сохраняя результат в `output/`.
4. Вы читаете готовые главы и точки контроля (журнал, аудит).

## Шаг 1. Установка (один раз)

Нужен Python 3.10+ (уже стоит) и две библиотеки:

```
python -m pip install pymupdf python-docx
```

## Шаг 2. Подготовка исходников тома

Положите в `D:\files\noverl\origs\` три файла тома NN:

| Файл | Что это |
|---|---|
| `NN-ja.epub` | японский оригинал |
| `NN-en.pdf` | английский перевод (текстовый PDF, не скан) |
| `NN-ru.docx` **или** `NN-ru.md` | русский перевод (машинный или правленный) |

Требования к RU-md (если у вас уже правленный перевод): абзацы разделены
пустой строкой, главы — заголовками `# Глава N: ...`. Совпадать по числу
абзацев с оригиналом НЕ обязательно.

## Шаг 3. Нормализация

Из папки `D:\files\noverl\` (не из AINovelEdit):

```
python tools/normalize.py --volume 14
```

Скрипт напишет статистику и создаст:
* `AINovelEdit/translates/{ja,en,ru}/vNN-*.md` — рабочие файлы (1 строка
  заголовка, далее абзацы через пустую строку; абзац №N одинаков во всех
  трёх языках);
* `AINovelEdit/translates/_report/vNN-alignment.md` — отчёт;
* `AINovelEdit/translates/_report/merged/vNN-*.md` — трёхъязычные копии
  для сверки глазами.

### Как читать отчёт выравнивания

| Колонка | Что значит | Когда тревожиться |
|---|---|---|
| JA/EN/RU абз. | сколько абзацев извлечено | — |
| Строк | строк в файлах после выравнивания | — |
| Пустых JA | позиций без японского абзаца | до ~15 на главу — норма |
| RU разрезано | склеенных RU-абзацев разрезано | — |

Если RU-разрезано 0 при большом разрыве между RU абз. и Строк — в
RU-источнике не хватает предложений, агент перепишет такие строки по JA.

## Шаг 3б. Изображения (вручную, раз на том)

Иллюстрации агенту не нужны для перевода, но понадобятся для итоговой склейки.
Запустите из папки `D:\files\noverl\`:

```
python tools/images.py --volume 14
```

Скрипт извлечёт картинки из EN-PDF в `images/v14/` и создаст
`images/v14/images.md` — таблицу, между какими EN-абзацами стоит каждая
иллюстрация (EN как эталон позиций, т.к. русский перевод будет меняться).
Эти файлы лежат вне проекта — агент с ними не работает.

При итоговой склейке перевод+иллюстрации позиции ищутся так: EN-абзац из
images.md → его номер в merged-файле → поле **ED_RU** (ваш отредактированный
перевод). Для этого агент после каждого блока обновляет merged-файл через
`scripts/update_merged.py` — в merged появился четвёртый столбец **ED_RU**
с готовым переводом (RU — старый машинный, ED_RU — отредактированный).

## Шаг 4. Словарь (5 минут перед запуском)

Откройте `AINovelEdit/dictionary.md`. Это единственный источник имён и
названий для агента. Просмотрите канонические варианты и примечания — там
может ждать ваше решение (например, перевод заголовков глав).
Ничего не добавляйте заранее: агент сам дописывает новые термины по ходу
работы с пометкой «новый (т.NN)».

## Шаг 5. Запуск агента

1. Откройте папку `D:\files\noverl\AINovelEdit` в Cline.
2. Дайте задачу. Два готовых варианта (копируйте):

**Первый запуск тома (с нуля, `output/` пуст):**

> Отредактируй том 14 по скиллам, начиная с главы 1, блока 1 (файл создавай
> через save_block.py --new). Полный цикл novel-editor для каждого блока:
> черновик → self-review → translation-audit → russian-humanizer →
> сохранение через save_block.py. Блоки по 10–20 абзацев. Все отклонения
> от источников вноси в журнал output/_log/v14-log.md, сомнительные места
> помечай <!-- ??? -->. Закончи блок, сохрани и остановись — дальше я скажу.

**Продолжение (в `output/` уже есть главы/блоки):**

> Продолжай редактирование тома 14 по скиллам, полный цикл novel-editor.
> Начни с первой неоконченной главы (прогресс виден по маркерам
> <!-- block: N --> в output/). Блоки по 10–20 абзацев, отклонения от
> источников — в журнал output/_log/v14-log.md, сомнительные места —
> пометка <!-- ??? -->.

Совет для первого запуска: последняя фраза «закончи блок и остановись» —
чтобы вы посмотрели на результат одного блока до запуска длинной работы.
Если стиль устраивает, дальше давайте промпт «Продолжай...» без ограничений.

Агент сам разберётся с флагом `--new` (первый блок главы создаёт файл заново,
остальные дописывают) — это прописано в его скилле save-progress.

### Ожидание

* Одна глава 14-го тома ≈ 176–364 абзаца ≈ 9–36 блоков — это долго,
  нормально. Один том ≈ 2800 абзацев.
* Возвращайтесь к разговору периодически: агент будет вести журнал и
  задавать вопросы через пометки.

## Шаг 6. Контроль процесса (пока агент работает)

| Где | Что смотреть |
|---|---|
| `output/vNN-*.md` | сам перевод; маркеры `<!-- block: N -->` = прогресс |
| `output/_log/vNN-log.md` | журнал: что удалено, что спорно, какие термины добавлены |
| `<!-- ??? -->` в тексте | места, требующие вашего решения |
| `output/_audit/vNN-chYY.md` | отчёт аудита после завершения главы |
| `translates/_report/merged/` | сверка перевода с JA/EN абзац к абзацу |

Сомнения из журнала — ваш список дел: по каждому решаете «оставить/поменять»
и говорите агенту.

## Шаг 7. После главы

1. Прочитайте `output/vNN-chYY.md` как художественный текст.
2. Найдите по журналу и аудиту все `<!-- ??? -->` и решите их.
3. Точечные правки можно делать двумя способами:
   * сами в любом редакторе (это обычный markdown);
   * попросить агента: «в главе ch01, абзац 42 замени на ...» — он использует
     `fix_block.py` (меняет только этот блок).
4. Если что-то не понравилось в целом (стиль, оформление реплик) — не
   просите переписать главу, а скажите агенту правило: он внесёт его в
   скилл, и все следующие блоки/главы пойдут правильно.

## Шаг 8. Следующий том

Повторить шаги 2–5 с новым номером. Словарь общий и уже наполненный —
каждый следующий том требует всё меньше внимания к терминам.

## Восстановление после сбоя

Прогресс не теряется: всё сохранено блоками в `output/`. Просто дайте
агенту ту же задачу из шага 5 — он продолжит с последнего незавершённого
блока. Повторный запуск нормализации безопасен: он пересоздаёт только
`translates/`, не трогая `output/`.

## Перепроверка готовых глав/блоков

Основной инструмент — скилл **translation-audit**: он сверяет готовый
русский текст поабзацно с EN (JA — арбитр), проверяет типографику,
обращения и машинность, исправляет через `fix_block.py` и пишет отчёт.

**Полная перепроверка сохранённой главы:**

> Проведи финальный аудит главы output/v14-ch01.md по скиллу
> translation-audit: сверка поабзацно с translates/en и translates/ja,
> проверка типографики (russian-prose-rules), обращений (forms-of-address)
> и машинности (russian-humanizer). Исправь однозначные ошибки через
> fix_block.py, рискованное — только предложения. Отчёт — в
> output/_audit/v14-ch01.md.

**Быстрая перепроверка конкретного фрагмента:**

> Перепроверь по скиллу translation-audit блок N файла v14-ch01.md
> (абзацы A–B): сверка с JA/EN, галлюцинации, оформление. Найденное —
> правки через fix_block.py + запись в журнал.

**Только стиль/машинность (без сверки с оригиналом):**

> Прогони главу v14-ch01.md через скилл russian-humanizer (все его
> ограничения из раздела «Ограничения в этом проекте» соблюдай), правки
> через fix_block.py, сомнительное — в журнал.

Учитесь различать: **аудит** ищет ошибки смысла и оформления; **humanizer**
в отдельном запуске — только «оживляет» слог. Для гарантированного качества
после массового прогона используйте первый вариант (он включает всё).

## Частые проблемы

**В тексте знаки `?` вместо букв.** Агент записал блок с испорченной
кодировкой (ловушка PowerShell). Скажите агенту: «блок N в файле X испорчен,
перезапиши через --text». Скрипт печатает размер файла: байты должны быть
заметно больше числа символов (кириллица в UTF-8 — 2 байта).

**Заголовок главы переведён неудачно.** Это нормально: по правилам аудита
агент обязан предлагать варианты, а не вписывать молча. Выберите вариант
из журнала/аудита и скажите, какой вписать.

**В EN есть предложения, которых нет в JA.** EN — фанатский перевод, там
бывают добавления переводчика. Политика: по умолчанию такое сохраняется
с пометкой `<!-- ??? -->` и записью СОМНЕНИЕ в журнал; решаете вы.

**Пустые строки `<!-- нет пары в JA -->`.** Не ошибка: японский абзац не
нашёл пары при выравнивании. Агент берёт смысл из EN/RU соседних позиций.

**RU-строка сильно длиннее соседних.** Склейка, которую не удалось разрезать
автоматически. Агент её перепишет по JA/EN при редактуре.

**ED_RU в merged «съехал» относительно EN-абзацев.** Две причины: (1) число
абзацев в output не совпало с EN (агент склеил два EN-абзаца в один — чаще
всего короткие реплики); (2) сам машинный RU-источник в этом регионе смещён
относительно EN. Скиллы запрещают склейку и требуют построчной сверки блока
с EN; при обнаружении скажите агенту: «проведи проверку соответствия строк
(translation-audit) по главе X, найди первую съехавшую строку и восстанови
разбиение по EN». Предупреждение `(!) ED_RU N != EN M` — сигнал первого
типа; съезд при равных числах строк ловит только построчная проверка.

## Карта файлов

```
AINovelEdit/
├── РУКОВОДСТВО.md      ← вы здесь
├── dictionary.md       # словарь имён/терминов (ваша истина)
├── translates/         # данные для агента (генерирует normalize.py)
│   ├── ja/ en/ ru/     # выровненные абзацы по главам
│   └── _report/        # отчёт выравнивания + merged-сверка
├── output/             # РЕЗУЛЬТАТ: готовый перевод
│   ├── vNN-chYY.md     # главы (это и есть конечный продукт)
│   ├── _log/           # журнал решений агента
│   └── _audit/         # отчёты аудита глав
├── scripts/            # save_block.py, fix_block.py (агенту)
└── .agents/skills/     # правила поведения агента (редактируйте под себя)
```

Конечный продукт — файлы в `output/`, начиная с `vNN-ch01.md`.
