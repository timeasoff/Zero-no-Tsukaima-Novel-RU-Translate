## 2. Изменения по трём проблемам

### Устойчивые усилительные конструкции JA

В рубрику «лексическая точность по JA» (контрастивная проверка лексической и
конструкционной точности) translation-audit добавлен общий подпункт:

1. выявление устойчивых усилительных/экспрессивных конструкций JA, где
   буквальный образ не обязан естественно воспроизводиться по-русски;
2. проверка не только буквального значения, но и ФУНКЦИИ конструкции в
   контексте (усиление отрицания, полное отсутствие, категоричность,
   экспрессивность);
3. различение случаев «образ сохранить» (авторский приём, стиль, повтор) и
   «передать функцию естественным русским оборотом»;
4. буквальный перевод НЕ считается ошибкой автоматически — учитываются
   контекст, авторский стиль, возможность естественного сохранения образа;
5. формально верный, но неестественный вариант → альтернатива со статусом
   `CANDIDATE`, без молчаливой правки (общее правило рубрики «Такие места по
   умолчанию — CANDIDATE»).

Правило сформулировано общим классом; `〜の〜の字も…ない` приведён только как
пример. В контрастивную таблицу (Human Gold Standard) добавлена эталонная
строка «Усилительная конструкция JA» с проверенной человеком парой v3-ch01:
«…и буквы „Г“ из его имени не упомянула» → «…даже словом о нём не
обмолвилась».

Дублирования нет: контрастивный признак «образ ↔ функция» — зона
translation-audit (как и у соседнего подпункта «конструкционная калька»);
стилистическая сторона выбранного русского оборота явно отнесена к
russian-style-audit (ссылка, не повтор инструкции). self-review п. 3 уже
ссылается на «лексическая точность по JA» — не дублировался.

## 4. Защита от false positives

* **Усилительные конструкции.** Правило — про контрастивную проверку, а не
  про автозамену: по умолчанию `CANDIDATE`, «ноль правок — допустимый итог»
  (AGENTS.md). Буквальный перевод прямо защищён от автоматической квалификации
  как ошибки; решение принимается по контексту и стилю. Частный оборот не
  заведён отдельным правилом — только как пример общего класса, что исключает
  перенос правила на почву одного паттерна.
* **«Верданди».** Паттерн сканера узкий (`Верданде` с границами слова):
  каноническая «Верданди» в любом падеже не затрагивается (5 негативных
  кейсов), соседние слова («Дерф», «Реконкисты») — не затрагиваются.
  Каноничность подтверждена решением пользователя (2026-09) и практикой
  ранних томов. Правило несклоняемости привязано к явной помете «не скл.»
  в словаре и запрещает аналогичное распространение на другие имена;
  склоняемые имена продолжают склоняться по правилам русского языка.
  Незафиксированные и PROVISIONAL/AMBIGUOUS формы — только `CANDIDATE`,
  массовая замена по подстроке запрещена. Сканер не правит текст — только
  сигнализирует.
* **Запрет коммитов.** Не ограничивает рабочие операции: read-only git
  (`status`/`diff`/`log`/`show`, drift_scan) разрешены; сужена только зона
  `git commit` и агентам явно разрешено предлагать коммит с описанием.
* **Общее.** Все правки — добавления к существующим правилам без удаления
  защит; статусные системы (`CANDIDATE`/`ERROR`, classification/disposition)
  использованы, а не заменены.


## 5. Непокрытые риски

* Различение «образ сохранить / функцию передать» для усилительных конструкций
  остаётся контекстным решением агента: механически этот класс не ловится и
  ловиться не должен (риск — вкусовщина; сдерживается `CANDIDATE` и эталонной
  таблицей). Требуется контроль на независимой главе с новыми JA-примерами.
* `NAME_TYPOS` ловит только подтверждённые схемы искажений: «Верданды»,
  «Верданду» и другие гипотетические падежи несклоняемого имени механически
  не детектируются (узкий паттерн по принципу консервативного расширения) —
  они закрываются контекстной проверкой translation-audit/self-review. При
  новой подтверждённой ошибке запись дополняется по тому же принципу.
* Склонение других несклоняемых имён по аналогии (например, «Кирхе», «Аньес»)
  механически не ловится: правило действует в контекстной сверке со словарём;
  надёжный автоматический чек потребовал бы отдельного механизма грамматических
  помет словаря — не реализован как неоправданный для единичного класса.
* Запрет коммитов закреплён инструкциями (AGENTS.md, save-progress);
  технической блокировки (hooks, скрипты) нет — агент с ослабленным контекстом
  может правило проигнорировать. При независимой проверке рекомендуется
  подтверждать, что агент предлагает коммит, а не выполняет его.
* Полный конвейер с обновлёнными правилами на независимой главе (например,
  v4-ch04) не прогонялся — регрессионные selftest покрывают сканеры, но не
  поведение агента целиком.

## 7. Вывод

Устранены три системные причины: (1) отсутствие контрастивного класса
«функция устойчивой конструкции ↔ буквальный образ» в translation-audit;
(2) отсутствие обязательной сверки падежных форм изменённых имён с каноном
(словарная помета «не скл.» не была подкреплена ни проверкой, ни примерами,
ни механическим сигналом); (3) отсутствие явного верховного запрета на
коммиты. Все решения — расширение существующих механизмов (рубрики
translation-audit, п. 2 terminology-dictionary, п. 4 self-review, словарь
`NAME_TYPOS` чека namespell, секция AGENTS.md); ни один существующий сканер
или skill не переписан и не ослаблен; канонические данные словаря и тексты
источников/томов не изменялись.

На независимой главе дополнительно проверить: распознавание новых
усилительных конструкций JA (функция vs образ) с корректным статусом
`CANDIDATE`; отсутствие склонения несклоняемых имён при редактуре; что
агент при завершении работы предлагает коммит, а не выполняет его.
