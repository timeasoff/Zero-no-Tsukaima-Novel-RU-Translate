# `tools/apply_agent_patch.py` — безопасное применение патчей

Скрипт предназначен для локального клона репозитория. Когда ChatGPT или другой агент не может редактировать GitHub напрямую, он может подготовить стандартный unified diff (`.patch`), а владелец репозитория применит его локально этим инструментом.

Скрипт **не подключается к GitHub и не загружает/не отправляет код**. Он работает только с локальным рабочим деревом Git.

## Установка

Скопируйте `apply_agent_patch.py` в папку `tools/` репозитория. Требуются Python 3.10+ и Git; сторонние Python-пакеты не нужны.

## Обычный сценарий

1. Получите от агента файл патча, например `audit-skill-fix.patch`, и положите его, например, в `patches/`.
2. Из корня репозитория сначала выполните проверку без изменений:

   ```bash
   python tools/apply_agent_patch.py patches/audit-skill-fix.patch
   ```

3. Если список файлов и проверка корректны, примените патч:

   ```bash
   python tools/apply_agent_patch.py patches/audit-skill-fix.patch --apply
   ```

4. Просмотрите изменения и прогоните проверки проекта:

   ```bash
   git diff --check
   git diff
   ```

5. Закоммитьте изменения обычным Git-процессом. Скрипт сам ничего не коммитит и не пушит.

## Получение патча через stdin

Если патч сохранён в файл, лучше указывать его путь. Также можно передать содержимое через stdin:

```bash
cat patches/my-change.patch | python tools/apply_agent_patch.py -
```

Команда выше только проверит patch. Для применения добавьте `--apply`. Не используйте `git diff | ...` для уже изменённого текущего рабочего дерева: такой diff описывает изменения, которые уже присутствуют, и повторное применение закономерно не пройдёт.

## Безопасность и откат

- По умолчанию режим preview: файлы не меняются.
- Перед записью выполняется `git apply --check`.
- По умолчанию перед применением делается резервная копия затрагиваемых файлов в Git metadata directory (`git rev-parse --git-path agent-patch-backups`), не в отслеживаемую папку проекта.
- При ошибке фактического применения скрипт пытается автоматически восстановить исходное состояние.
- Скрипт отказывается от абсолютных путей, путей с `..` и путей, проходящих через symlink.
- Он не делает commit, push, force-push и не взаимодействует с сетью.
- Текстовые изменения с завершающими пробелами по умолчанию отклоняются (`--whitespace=error-all`). Если это намеренно, можно явно выбрать `--whitespace warn`.

Показать список изменений без записи — достаточно вызвать скрипт без `--apply`.

## Откат ранее применённого патча

После применения скрипт выведет расположение резервной копии. Сначала просмотрите план восстановления:

```bash
python tools/apply_agent_patch.py --restore ".git/agent-patch-backups/<backup-id>"
```

Затем выполните восстановление:

```bash
python tools/apply_agent_patch.py --restore ".git/agent-patch-backups/<backup-id>" --apply
```

В Git worktree или при нестандартном расположении `.git` используйте точный путь, который напечатал скрипт. Откат восстанавливает файлы до состояния непосредственно перед применением и может перезаписать последующие изменения в этих файлах, поэтому перед восстановлением внимательно проверьте список.

## Полезные параметры

```bash
# Указать корень репозитория явно
python tools/apply_agent_patch.py changes.patch --root .

# Применить патч в обратном направлении (перед этим будет preview)
python tools/apply_agent_patch.py changes.patch --reverse
python tools/apply_agent_patch.py changes.patch --reverse --apply

# Патчи с другим количеством префиксов пути
python tools/apply_agent_patch.py changes.patch --strip 0

# Не создавать резервную копию (не рекомендуется)
python tools/apply_agent_patch.py changes.patch --apply --no-backup
```

Формат входа — обычный unified diff, предпочтительно сгенерированный `git diff` или `git format-patch`.
